# TaskFlow 下一步开发计划与最终目标

> 状态：生效
> 版本：v1.0
> 最后更新：2026-09-13
> 适用范围：MVP 收尾、国内部署练习、面试交付

## 1. 最终目标

TaskFlow 是面向个人开发者的 AI 任务协作平台。最终交付链路为：

登录 → Workspace 隔离 → 创建/编辑/删除 Issue → 列表与看板切换 → 拖拽改状态 → AI 拆解需求 → 用户编辑确认 → 子任务事务批量创建。

工程交付必须同时满足：

- Next.js 16 App Router、React Server/Client Component 边界清晰。
- Auth.js Credentials + JWT、Workspace 授权和输入校验有自动化回归。
- AI 仅在服务端调用，具备结构化解析、超时、错误映射、限流和幂等。
- Jest、Playwright、冒烟、Lint、TypeScript、Build 均有可重复的质量门禁。
- Docker Compose、腾讯云 Lighthouse/ECS、Nginx、HTTPS、迁移、备份和恢复步骤可复现。
- 面试材料能用代码位置、测试结果和性能数据证明关键设计。

## 2. 当前基线

- 核心 MVP 链路已经可运行。
- `proxy.ts` 已存在；业务入口仍必须执行服务端鉴权和 Workspace 授权。
- Jest：11 个测试套件、31 个用例；已进入 CI。
- Playwright：已接入基础用例，尚未覆盖完整业务闭环，暂未进入 CI。
- 冒烟脚本：定义 40 项检查，实际执行数受环境自适应策略影响。
- 看板拖拽：使用 `pendingIds` 串行化，请求在途期间禁止新的拖拽，失败按快照回滚。
- Redis 限流、独立迁移 Job、多实例发布和回滚演练尚未完成。

## 3. 下一步执行计划

### Sprint 5：核心自动化验证（1 周，30-40 小时）

目标：把 AI 路由、注册并发和看板关键行为变成稳定的自动化证据。

入口条件：Jest 基线通过；本地应用和测试数据库可启动；无未解释的 P0/P1 构建错误。

任务：

1. 补充 AI Route 测试：未登录 401、非法输入 400、超时 504、不可重试上游错误不得重复调用。
2. 补充注册并发测试：同一邮箱并发请求只创建一个用户，其余请求映射为统一 `CONFLICT`。
3. 补充看板串行策略测试：存在 `pendingIds` 时不发送第二次请求，失败后恢复快照并解除阻塞。
4. 使用 Mock Provider 覆盖成功、无效输出、超时和上游 5xx 重试；真实 Key 不进入测试和 CI。
5. 接入 Playwright：注册 → 登录 → 创建 Issue → 修改状态 → 刷新验证。
6. 稳定后将关键 Playwright 用例纳入 CI。

出口条件：上述测试稳定通过；质量命令 `npm run lint`、`npm run format:check`、`npx tsc --noEmit`、`npm test`、`npm run build` 全部通过。

不做：并发拖拽 last-write-wins、Vue 页面、新 AI 功能。

### Sprint 6：国内单实例部署（1 周，30-40 小时）

目标：在腾讯云完成可访问、可迁移、可恢复的单实例部署练习。

任务：准备 Lighthouse/ECS、Docker、Nginx 和 HTTPS；生产 `.env` 只保存在服务器；执行 `prisma migrate deploy`；完成备份、恢复和重启后数据保持演练；配置可信代理和真实 IP；脱敏健康检查和异常日志。

出口条件：国内 HTTPS 地址可访问，登录、Issue、看板、AI 闭环可演示；服务器重启后应用和数据恢复；`.env`、API Key、证书私钥和敏感日志未进入 Git。

### Sprint 7：公网多实例前置（1-2 周，30-40 小时/周）

目标：解决跨实例共享状态和发布一致性问题后，才允许扩大访问范围。

必须完成：

1. 将内存限流抽象为 Store 并接入 Redis；Redis 不可用时统一拒绝并返回 429。
2. 将数据库迁移拆为独立 Job；迁移失败必须阻断应用发布。
3. 演练多实例滚动发布、回滚和迁移失败场景。
4. 验证实例间 Session、限流计数和日志行为一致。
5. 更新运维手册和故障告警。

出口条件：两个实例共享限流计数；迁移失败不会启动新版本；回滚有命令、日志和结果记录。

### Sprint 8：面试化收尾（3-5 天，20-30 小时）

目标：将已完成能力转化为可验证、可讲解的作品。

任务：填写 `docs/04-interview/interview-evidence.md`；准备不超过 5 分钟的完整演示；记录拖拽 SQL 重写前后性能、AI 错误映射、密钥边界、限流和幂等策略；补充 React 与 Vue 原理对比；完成一次从零部署演练并保存测试和 CI 证据。

出口条件：演示无需手工改库；README、架构、ADR、测试、运维和面试证据相互一致；未完成能力明确标记为 Backlog。

## 4. 统一降级顺序

时间不足时依次移除：Vue 对比页面、动画和视觉增强、搜索筛选标签、AI Token 展示层、非关键 Playwright 场景。

不得降级：认证、Workspace 权限、Issue CRUD、AI 服务端密钥隔离、数据库迁移、备份恢复、公网多实例前的 Redis 限流和迁移失败阻断。

## 5. 最终完成定义

只有同时满足以下条件，才可将项目标记为完成：

- MVP 核心链路可从零演示。
- 国内单实例部署和恢复演练通过。
- 若开放多实例，Redis、迁移 Job、发布和回滚演练全部通过；否则明确限制为单实例。
- 自动化测试和质量门禁通过。
- 文档中的版本、状态、测试数量和代码实现一致。
- Git 提交只包含当前任务文件，不提交密钥、构建产物或无关文件；文档是否提交按当前任务约束执行。
