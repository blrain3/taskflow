# TaskFlow Definition of Done

> 状态：生效
> 维护阶段：所有开发阶段
> 关联文档：[文档中心](../README.md)、[User Stories](../01-product/user-stories.md)、[提交规则](commit-rules.md)

一个 Story 只有满足以下全部条件，才能标记为 Done。

## 1. 需求完成

- [ ] User Story 的业务目标已实现。
- [ ] 所有 Given-When-Then 验收标准通过。
- [ ] 正常流程已验证。
- [ ] 至少一个失败或异常流程已验证。
- [ ] 空状态、加载状态和错误状态已处理。

## 2. 代码质量

- [ ] 使用 TypeScript strict。
- [ ] 没有新增未解释的 `any`。
- [ ] 服务端逻辑与 UI 逻辑职责分离。
- [ ] Server Action 和 API Route 有明确输入输出类型。
- [ ] 共享类型放在 `types/` 或对应领域模块中。
- [ ] 没有重复实现明显相同的业务规则。
- [ ] 复杂逻辑有简短注释或 ADR 说明。

## 3. 安全和数据

- [ ] 所有受保护入口都校验 Session。
- [ ] 所有 Workspace 数据访问都执行归属校验。
- [ ] 用户输入经过 Schema 校验。
- [ ] AI Key 和数据库连接信息没有进入客户端。
- [ ] 错误响应不泄露敏感信息。
- [ ] 数据库迁移可重复执行。
- [ ] 删除和批量写入行为符合预期。

## 4. 自动化验证

- [ ] `npm run lint` 通过。
- [ ] `npm run format:check` 通过。
- [ ] `npm run build` 通过。
- [ ] `npm test`（Jest 单元测试）通过，新增业务行为有对应测试。
- [ ] 当前阶段至少通过 `npm run smoke`；E2E 用例覆盖相关路径时 `npm run test:e2e` 通过。
- [ ] 修改已有行为时，已有测试仍然通过。
- [ ] 关键缺陷已添加回归测试。
- [ ] RTL 组件测试接入前，涉及 UI 行为的 Story 在交付记录中登记该缺口。

## 5. 用户体验

- [ ] 提交按钮在请求期间防止重复提交。
- [ ] 请求失败后用户可以重试或恢复。
- [ ] 页面没有明显布局跳动或内容重叠。
- [ ] 键盘可以完成基本表单操作。
- [ ] 主要页面在目标桌面分辨率下可用。
- [ ] 重要按钮和输入具有明确的可访问名称。

## 6. 文档和交付

- [ ] README 已更新。
- [ ] 相关 ADR 已更新。
- [ ] 架构或数据流变化已记录。
- [ ] 面试证据文档已补充代码位置和验证结果。
- [ ] 预览环境部署成功。
- [ ] 验收链接或截图已保存。

## 7. Git 和 CI

- [ ] 提交信息符合 `commit-rules.md`：中文、最多两句话、不加英文 `type(scope):` 前缀。
- [ ] 分支只包含当前 Story 的相关变更。
- [ ] CI 中当前已配置的 lint、format、build、test 均通过；E2E 用例扩充后再增加 test:e2e 门禁。
- [ ] 没有提交 `.env`、API Key 或本地数据库文件。
- [ ] PR 或自审记录包含变更摘要、风险和测试结果。

## 8. 不满足 DoD 时的处理

如果任何必选项未完成：

1. Story 不得标记为 Done。
2. 将缺失项记录为明确的待办事项。
3. 如果影响核心安全、数据正确性或测试，必须留在当前 Sprint。
4. 如果只是文档或视觉优化，可降级到后续 Backlog。
