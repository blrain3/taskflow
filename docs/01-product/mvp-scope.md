# 第一阶段 MVP 范围：单人写作平台

> 状态：提案，待产品方向确认
> 版本：v2.0
> 最后更新：2026-09-13
> 关联：`adr-007-writing-platform-direction.md`、`document-data-model-proposal.md`

## 1. 产品定位

TaskFlow 重构为面向个人开发者和小型工作组的文档写作平台。第一阶段只验证“用户能安全地创建、编辑、保存和恢复自己的文档，并使用 AI 辅助写作”的单人写作闭环。

第一阶段不承诺多人实时同时编辑；成员权限只用于 Workspace 级访问控制和后续扩展准备。

## 2. 第一阶段做什么

| 优先级 | 能力 | 验收结果 |
|---|---|---|
| P0 | 注册、登录、登出 | 复用 Auth.js，未登录不能访问工作区 |
| P0 | Workspace 与成员邀请 | 用户可进入 Workspace；邀请记录可创建、查看和接受，权限由服务端校验 |
| P0 | 文档创建、编辑、保存 | 用户可创建标题和 Markdown/富文本正文，保存后刷新数据不丢失 |
| P0 | 文档列表 | 只显示当前用户有权访问的文档，支持按更新时间排序 |
| P0 | 权限控制 | 非成员不能读取、修改或删除文档 |
| P0 | 自动保存 | 编辑停止一段时间后自动保存；请求进行中显示状态，失败可重试 |
| P0 | 文档版本历史 | 每次成功保存生成版本，可查看版本列表和恢复指定版本 |
| P1 | AI 大纲生成 | 服务端根据主题生成结构化大纲，失败不写入正文 |
| P1 | AI 润色 | 用户选中文本或正文后请求润色，结果需人工确认后覆盖 |
| P1 | AI 摘要 | 根据正文生成摘要，结果可复制或保存到文档摘要字段 |
| P1 | 测试与部署 | Jest、Playwright、CI、Docker 和国内单实例部署证据齐全 |

## 3. 第一阶段不做什么

- 不实现 WebSocket、SSE 实时同步、CRDT、OT 或在线光标。
- 不实现评论、审阅流、@提及、通知、分享链接和公开发布。
- 不实现多人同时编辑冲突合并；同一文档并发保存只做版本号校验并提示用户刷新。
- 不实现复杂富文本排版、协同白板、附件管理和全文搜索。
- 不保留 Issue 看板作为新产品核心；原 Issue 模块仅保留为历史模块和回归参考。
- 不增加多模型路由、AI 周报、AI 推荐等非写作能力。

## 4. 优先级与范围控制

P0 必须完成后才进入部署验证；P1 AI 能力至少完成大纲、润色、摘要中的一个稳定闭环，其余可按时间降级为只读结果；任何实时协作需求进入第二阶段 Backlog，不得插入第一阶段 Sprint。

## 5. MVP 完成定义

- 新用户可注册、登录并进入 Workspace。
- 用户可创建文档、编辑正文、自动保存并在刷新后恢复。
- 文档列表严格遵守 Workspace 成员权限。
- 用户可以查看版本历史并恢复一个历史版本。
- AI 调用只发生在服务端，超时、无效输出和上游错误不会污染正文。
- 核心链路有 Jest/Playwright/HTTP 冒烟证据，Docker Compose 可重复启动。

## 6. 第二阶段候选 Backlog

实时协作、评论与审阅、文档分享/发布、版本差异对比、通知、全文搜索、附件、团队角色细分和协同编辑性能优化。
