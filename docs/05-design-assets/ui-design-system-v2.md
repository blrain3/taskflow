## 1. 设计目标与设计原则

### 1.1 设计目标

TaskFlow 的界面必须同时服务两个目标，且这两个目标在本项目里同等重要：

1. **好用**：让一个技术背景用户在 10 秒内把脑子里的念头变成一条可追踪的任务。
2. **可讲解**：让一个初次打开产品的面试官在 5 秒内看懂「这是一个会用 AI 拆任务的看板」，并在 5 分钟内看到视觉与交互的专业度。

第 2 条是本项目特有的约束。它决定了几件事：首屏必须自解释、空状态必须引导、任何一步操作都不允许出现白屏或未处理状态。

### 1.2 五条设计原则

| # | 原则 | 含义 | 违反示例 |
|---|---|---|---|
| P1 | **内容优先** | 界面是任务的容器，不是主角。装饰性元素一律删掉，层级靠留白与对比建立 | 给卡片加渐变背景、给按钮加投影光晕 |
| P2 | **键盘平行** | 鼠标能做的事键盘都能做，且更快。所有交互有键盘替代方案 | 拖拽只能拖，不能用键盘移动卡片 |
| P3 | **状态诚实** | idle / loading / empty / error / success 五态必须全部被设计。绝不展示虚假成功 | 请求还在飞就先把列表改成成功态 |
| P4 | **密度自选** | 同一套令牌支持「紧凑 / 舒适」两档密度，不改动任何组件实现 | 为紧凑模式重写一套组件 |
| P5 | **深浅同源** | 深浅主题是同一套语义令牌的变量替换，不是两套设计 | 深色配色写一套 hex，浅色再写一套 |

> **原则 P3 的强制边界**：`architecture.md` §11 已定义五态状态机。本方案要求每个异步交互在设计稿上显式画出五态，缺少任一态视为设计未完成，不接受「开发时再说」。

## 2. 目标用户、使用场景与适配平台

### 2.1 用户画像

| 画像 | 角色 | 特征 | 核心诉求 | 优先级 |
|---|---|---|---|---|
| **U1 主力用户** | 独立开发者 / 小团队技术负责人，26–35 岁 | 每天 8 小时以上在 IDE 与终端；任务来源零散（PR 评审、缺陷、临时想法）；用过 Jira 觉得太重、用过便签觉得留不住 | 记录摩擦极低、键盘优先、信息密度高、AI 帮我把一句话拆成可执行清单 | **最高** |
| **U2 次要用户** | 多任务并行的学习者 / 求职者（即项目作者本人） | 同时推进学习、项目、面试准备；需要在有限时间内掌控全局 | 一眼看清「今天要做什么」，能快速重排优先级 | 高 |
| **U3 演示受众** | 面试官 / 技术评审 | 停留 3–5 分钟，通过投屏观看；关注工程细节与产品完整度 | 首屏 3 秒内理解产品价值；随便点几下都不会看到破绽 | 高（约束设计下限） |
| **U4 路过用户** | 手机端用户 | 通勤或会议间隙打开看一眼 | 只看「今天该干什么」，不需要完整操作 | 中（决定响应式降级策略） |

**关键推论**：U1 和 U3 的诉求存在天然张力——U1 要信息密度高，U3 要一眼看懂。解决方案不是折中，而是**分层**：默认视图保持高密度以服务 U1；同时用「概览页统计卡 + 空状态引导 + 零破绽的错误处理」来满足 U3。

### 2.2 使用场景矩阵

| 场景 | 设备与尺寸 | 时长 | 用户主要动作 | 设计对策 |
|---|---|---|---|---|
| S1 全天候工作台 | 桌面 1440–2560，可能双屏 | 30 分钟–6 小时 | 看板拖拽、创建、编辑、反复切换视图 | 侧边栏常驻、快捷键全覆盖、URL 承载视图状态、长时间停留不留视觉疲劳（低饱和、无动画噪音） |
| S2 想法瞬时捕获 | 桌面，从 IDE 切过来 | 5–15 秒 | 按 `N` → 输入一句话 → 回车 | 全局快捷键、抽屉自动聚焦、⌘Enter 提交、关闭即入库 |
| S3 AI 批量规划 | 桌面 | 1–3 分钟 | 粘贴一段需求描述，审阅并修正 AI 输出 | 结果可编辑/可删/可重生成、逐条确认、批量创建带事务语义 |
| S4 投屏演示 | 1920×1080 投屏 | 3–5 分钟 | 走完整闭环 | 字号在 1080p 投屏下可读、关键操作有可见反馈、演示路径 ≤5 分钟（对齐 `sprint-plan.md` Sprint 4 出口条件） |
| S5 移动端速览 | 手机 360–430 | 30–60 秒 | 看今天有什么、把某条标为完成 | 列表优先、底部 Tab、无拖拽（改长按选状态）、只读为主 |
| S6 平板轻操作 | 平板 768–1024 | 3–10 分钟 | 浏览、创建、改状态 | 侧边栏抽屉化、看板单列滑动、触控目标 ≥44px |

### 2.3 适配平台与断点策略

**主力平台：桌面端 Web。** 不做原生 App（`mvp-scope.md` P2 已明确排除）。

| 断点 | 名称 | 目标设备 | 布局行为 |
|---|---|---|---|
| `< 360px` | — | — | 不支持；低于此宽度显示提示页 |
| `360–767px` | `sm` | 手机 | 底部 Tab 导航；隐藏侧边栏；看板降级为列表；无拖拽 |
| `768–1023px` | `md` | 平板 | 侧边栏转抽屉（汉堡按钮唤起）；看板单列 + 列切换 Tab |
| `1024–1279px` | `lg` | 小笔记本 | 侧边栏折叠为 56px 图标轨（悬停展开浮层）；看板 4 列横向滚动 |
| `1280–1439px` | `xl` | 主流笔记本 | **设计基准区间**；侧边栏 240px 常驻；看板 4 列完整；详情抽屉覆盖式 |
| `≥ 1440px` | `2xl` | 外接显示器 / 双屏 | 侧边栏常驻；看板 4 列留白放宽；详情抽屉并排显示（不覆盖内容） |

**多输入方式**：鼠标 + 键盘（主力）、触控（平板/手机）、投屏遥控翻页笔（仅需支持方向键）。

## 3. 设计令牌系统（Design Tokens）

### 3.1 三层令牌架构

v1.0 的问题在于直接罗列十六进制色值，导致「换个主题要改一遍全部代码」。v2 采用三层结构：

```
Layer 1  原始令牌 (Primitive)   --ink-950: #0B0B0D      只定义，不直接使用
        ↓
Layer 2  语义令牌 (Semantic)    --bg-canvas: var(--ink-950)
        ↓                                               组件只允许引用这一层
Layer 3  组件令牌 (Component)   --card-padding: var(--space-3)
                                                        仅在组件有特殊需求时新增
```

**硬性规则**：任何组件样式不得直接引用 Layer 1。换肤、调暗、改密度都只动 Layer 2。

### 3.2 色彩系统

命名规则：`--{类别}-{角色}[-{状态}]`，一律使用语义名而非颜色名（不写 `--purple`，写 `--brand-500`）。

#### 3.2.1 表面与文字（深色为默认）

| 语义令牌 | 深色值 | 浅色值 | 用途 | 对比度 |
|---|---|---|---|---|
| `--bg-canvas` | `#0B0B0D` | `#FFFFFF` | 应用最底层画布 | — |
| `--bg-surface` | `#111114` | `#FAFAFB` | 侧边栏、看板列背景 | — |
| `--bg-raised` | `#17171B` | `#FFFFFF` | 卡片、抽屉、弹窗 | — |
| `--bg-overlay` | `#1D1D22` | `#FFFFFF` | 悬浮菜单、命令面板 | — |
| `--bg-hover` | `rgba(255,255,255,.055)` | `rgba(0,0,0,.045)` | 悬停态填充 | — |
| `--bg-active` | `rgba(255,255,255,.09)` | `rgba(0,0,0,.07)` | 按下 / 选中态填充 | — |
| `--border-subtle` | `rgba(255,255,255,.07)` | `rgba(0,0,0,.08)` | 默认分割线与卡片边框 | — |
| `--border-default` | `rgba(255,255,255,.12)` | `rgba(0,0,0,.14)` | 输入框、悬停强调 | — |
| `--border-strong` | `rgba(255,255,255,.20)` | `rgba(0,0,0,.22)` | 焦点容器、拖拽投放区 | — |
| `--text-primary` | `#F2F2F5` | `#14141A` | 标题、正文、任务名 | **17.6 : 1** ✓ |
| `--text-secondary` | `#A0A0AC` | `#5C5C68` | 描述、元信息、次要标签 | **7.3 : 1** ✓ |
| `--text-tertiary` | `#6E6E7A` | `#8A8A96` | 时间戳、计数、占位符 | 3.6 : 1 ⚠️ 仅限 ≥16px 或非关键信息 |
| `--text-inverse` | `#0B0B0D` | `#FFFFFF` | 反色场景（浅色填充按钮上的文字） | — |

> ⚠️ `--text-tertiary` 未达 WCAG AA 正文标准（4.5:1）。使用约束：不得承载用户必须读到的信息（如任务标题、错误提示）。它只能用于「时间戳、数量、占位提示」这类可推断或非必要的内容。

#### 3.2.2 品牌色

| 语义令牌 | 深色值 | 浅色值 | 用途 |
|---|---|---|---|
| `--brand-500` | `#6E5BF6` | `#5B48E0` | 主按钮底色、激活项、链接 |
| `--brand-hover` | `#7F6EFF` | `#4B39CC` | 主按钮悬停 |
| `--brand-subtle` | `rgba(110,91,246,.16)` | `rgba(91,72,224,.10)` | 选中行背景、AI 区块底 |
| `--brand-text` | `#A99BFF` | `#4A3AB8` | 品牌色文字（深色下提亮以保证对比） |
| `--focus-ring` | `#8B7CFF` | `#5B48E0` | 焦点环 |

> 主按钮白字对 `--brand-500` 的对比度为 **4.7 : 1**（深色）/ **6.1 : 1**（浅色），满足 AA。
>
> **相对 v1.0 的调整**：v1.0 用紫色同时承担「品牌强调」与「进行中状态」，二者会在看板上互相干扰。v2 把紫色**独占给品牌与交互**，状态色改用中性可辨识的家族，并参考 Linear 的实际做法（Backlog 灰 / Todo 蓝 / In Progress 黄 / Done 绿）。

#### 3.2.3 状态色（对应数据库枚举）

| 语义令牌 | 深色值 | 浅色值 | 枚举值 | 中文标签 |
|---|---|---|---|---|
| `--status-backlog` | `#85858F` | `#6B6B76` | `BACKLOG` | 待整理 |
| `--status-todo` | `#5B8DEF` | `#2563EB` | `TODO` | 待开始 |
| `--status-progress` | `#D9A03C` | `#B45309` | `IN_PROGRESS` | 进行中 |
| `--status-done` | `#3FA65C` | `#15803D` | `DONE` | 已完成 |

状态色作为文字的对比度均 **≥ 5.0 : 1**，可安全用于列标题与状态标签。

#### 3.2.4 语义反馈色

| 令牌 | 值 | 用途 |
|---|---|---|
| `--color-danger` | `#E5484D` | 删除、危险操作、错误提示 |
| `--color-success` | `= --status-done` | 操作成功 |
| `--color-warning` | `= --status-progress` | 需要注意（如 AI 输出可能不准确） |
| `--color-info` | `= --status-todo` | 中性提示 |

#### 3.2.5 优先级色（P1 功能，先定义后实现）

| 令牌 | 值 | 说明 |
|---|---|---|
| `--priority-urgent` | `#E5484D` | 紧急 |
| `--priority-high` | `#E5863C` | 高 |
| `--priority-medium` | `--text-secondary` | 中（中性，不额外着色） |
| `--priority-low` | `--text-tertiary` | 低 |

> **无障碍铁律**：颜色永不作为唯一信息载体。状态色必须与状态文字并列出现；优先级必须同时有颜色 + 图标（箭头）。色盲用户仅凭颜色也能正确解读。
>
> **注意**：任务状态用「绿 = 完成」是产品语义约定，与金融行情的涨跌配色无关，不受红涨绿跌惯例影响。

### 3.3 字体系统

**字体栈**（通过 `next/font` 加载 Inter，中文走系统字体以避免体积膨胀）：

```css
--font-sans: Inter, -apple-system, "PingFang SC", "HarmonyOS Sans SC",
             "Microsoft YaHei", "Noto Sans SC", sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, monospace;
```

**字阶**（工具型产品，基准 14px 而非 16px，以换取信息密度）：

| 令牌 | 字号 / 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `display` | 32 / 40 | 600 | -0.02em | 空状态主标题、AI 结果页标题 |
| `h1` | 24 / 32 | 600 | -0.015em | 页面标题（概览、设置） |
| `h2` | 20 / 28 | 600 | -0.01em | 区块标题 |
| `h3` | 16 / 24 | 600 | -0.005em | 抽屉标题、看板列标题 |
| `body` | 14 / 22 | 400 | 0 | 描述、正文 |
| `body-strong` | 14 / 22 | 500 | 0 | 任务标题、按钮文字 |
| `small` | 13 / 20 | 400 | 0 | 辅助说明、表单提示 |
| `caption` | 12 / 16 | 500 | 0.01em | 标签、计数、快捷键提示 |
| `mono` | 13 / 20 | 500 | 0 | Issue ID、快捷键、代码片段 |

**中文排版约束**：
- 中文字号不得小于 12px，正文推荐 14px。
- 字重只使用 400 / 500 / 600，禁止 700 及以上（中文字体在浏览器中易被伪粗体渲染，笔画会糊）。
- 中英混排时依赖系统字体的 fallback 即可，不额外做字体切换。
- 英文标题的负字距（-0.02em）对中文无效，因此标题类令牌的负字距只作用于 Latin 字符范围。

#### 层级（深色下的关键差异）

深色界面里传统投影几乎不可见，v1.0 直接搬用浅色阴影体系是失效的。v2 的层级由**边框 + 极低透明度投影**共同表达：

| 令牌 | 深色 | 浅色 |
|---|---|---|
| `--elev-0` | 仅 `--border-subtle` | 仅 `--border-subtle` |
| `--elev-1` | `0 1px 2px rgba(0,0,0,.4)` + `--border-default` | `0 1px 2px rgba(0,0,0,.06)` + `--border-subtle` |
| `--elev-2` | `0 8px 24px rgba(0,0,0,.5)` + `--border-default` | `0 4px 12px rgba(0,0,0,.10)` + `--border-subtle` |
| `--elev-3` | `0 16px 48px rgba(0,0,0,.6)` + `--border-strong` | `0 12px 32px rgba(0,0,0,.14)` + `--border-default` |

映射：卡片 hover → `elev-1`；拖拽中的卡片、下拉菜单 → `elev-2`；抽屉、命令面板、弹窗 → `elev-3`。

#### 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--dur-instant` | 80ms | 悬停、按下反馈 |
| `--dur-fast` | 120ms | 焦点环、标签切换 |
| `--dur-base` | 180ms | 抽屉滑入、下拉展开、卡片落位 |
| `--dur-slow` | 240ms | 页面级过渡、视图切换 |
| `--ease-out` | `cubic-bezier(0.2, 0, 0, 1)` | 默认（入场、位移） |
| `--ease-in-out` | `cubic-bezier(0.4, 0, 0.2, 1)` | 双向过渡 |
| `--ease-spring` | `cubic-bezier(0.34, 1.4, 0.64, 1)` | **仅**用于拖拽落位与弹层入场 |

**禁止清单**：时长超过 400ms、弹跳式过冲（除上述唯一例外）、阴影呼吸、渐变闪烁、页面加载动画（loading 用骨架屏而非旋转标志长时间占据主区域）。

**降级**：`@media (prefers-reduced-motion: reduce)` 下所有时长归零，仅保留透明度变化，位移与缩放取消。

### 4.1 站点地图

```
TaskFlow
├─ (公开) 认证区
│  ├─ /login                        登录（保留 redirect 参数）
│  └─ /register                     注册
│
└─ (受保护) 工作区应用外壳
   ├─ /overview                     概览 —— 登录后默认落地页        [P1]
   ├─ /issues                       任务主工作区（?view=board|list） [P0]
   │   └─ ?issue=TF-142             详情以抽屉形式叠加（可分享链接）[P0]
   ├─ /ai                           AI 拆解独立入口                  [P0]
   └─ /settings                     账户 / 主题 / 快捷键 / 危险区    [P1]

全局浮层（不占路由）
   ├─ 命令面板          ⌘K / Ctrl+K

   └─ 确认弹窗          仅用于不可撤销操作
```

**信息架构规则**：
1. **三层可达**：从任意页面到达任意对象不超过 3 次点击。
2. **视图状态进 URL**：`?view=`、`?status=`、`?q=`、`?issue=` 全部写入 URL，保证可分享、可后退、可刷新还原（对应 `architecture.md` §7.1 通道 D）。
3. **浮层不占路由**：抽屉与命令面板不改变 URL 层级，避免「关掉抽屉后浏览器后退到奇怪位置」。
4. **对象详情双形态**：桌面为右侧抽屉（保持上下文不丢失），移动端为整页跳转（`/issues/[id]`）。

1. 只有内容区（③）滚动。顶部栏与侧边栏固定，不参与滚动。

## 5. 核心页面流程

### 流程 A · 首次访问与认证

```
访问任意受保护路由
  → 无 Session → 302 到 /login?redirect=/issues
  → 登录成功 → 检查 Workspace
      ├─ 无 Workspace → 引导创建弹窗（预填「我的工作区」，一键确认）
      └─ 有 Workspace → 回到 redirect 目标（缺省 /overview）
```

**设计要点**：登录页左右分栏——左侧品牌区（Logo + 一句「用 AI 把想法变成可执行的任务」），右侧登录卡片。登录失败统一提示「邮箱或密码不正确」，不区分用户是否存在（对齐 `architecture.md` §8.1 安全要点）。

### 流程 B · 日常主循环（最高频）

```
打开应用 → /overview 概览
  → 点击统计卡「进行中 5」→ /issues?view=board&status=IN_PROGRESS
  → 拖拽卡片到「已完成」
      → ① 本地立即落位（乐观更新），落位动画 180ms
      → ② 服务端确认成功 → 卡片收敛，右下 Toast「已移动到已完成 · 撤销」保留 5s
      → ③ 服务端失败 → 卡片回弹至原列，Toast「移动失败，已还原」+ 重试入口
```

### 流程 C · 快速捕获（目标 <10 秒）

```
任意页面按 N（非输入态）
  → 右侧抽屉滑入 180ms，焦点自动落在标题输入框
  → 输入标题（可选描述），⌘Enter 提交
  → 提交中：按钮进入 loading 且禁用（防重复提交）
  → 成功后：抽屉关闭，目标列顶部插入新卡片并高亮 1s，Toast 确认
  → Esc / 点击遮罩取消：草稿在本地保留 5 分钟，再次打开自动恢复
```

### 流程 D · 视图切换与筛选

```
工具栏分段控件 [看板 | 列表] → 写入 ?view=board|list（pushState）
  → 筛选 chip（状态/优先级）→ 写入 ?status=...&priority=...
  → 搜索框 → 写入 ?q=...（防抖 300ms）
  → 全部写入 URL：可后退、可刷新还原、可复制链接分享
  → 无结果时显示「无匹配任务」空状态，并提供「清除全部筛选」主动作
```

### 流程 E · AI 拆解闭环（差异化能力）

```
入口（三选一）：侧边栏「AI 拆解」/ 命令面板「用 AI 创建」/ 新建抽屉内按钮
  → 输入自然语言（≥10 字符）
  → 分析中：骨架屏占位 + 可见的「取消」按钮（AbortController）
  → 结果页：子任务列表，每条可编辑标题、可删除、可调整优先级
      底部操作：[重新生成] [取消] [确认并创建全部]
  → 确认创建：按钮进入 loading 并禁用
  → 事务批量写入（全成功或全失败）
      ├─ 成功 → 跳转 /issues，新卡片高亮，Toast「已创建 N 个任务」
      └─ 失败 → 整体回滚，**保留用户的编辑结果**，原位显示重试入口
```

**三个失败分支的界面落点**（对齐 US-007 / US-008 验收标准）：
| 失败类型 | 界面表现 |
|---|---|
| AI 输出不合 Schema | 不写库；提示「生成结果格式异常，请重新生成」，保留原始输入 |
| 请求超时 | 停止加载；保留输入；显示「重新生成」按钮 |
| 批量写入失败 | 事务回滚；保留用户已编辑的子任务列表；显示「重试创建」 |

### 流程 F · 异常与空态（贯穿全部页面）

| 状态 | 界面表现 | 约束 |
|---|---|---|
| 加载 | 骨架屏，形状与真实内容一致 | 不跳版；超过 800ms 才显示骨架（避免闪烁） |
| 空数据 | 图标 + 标题 + 一句说明 + 唯一主动作 | 不得出现无主动作的空状态 |
| 请求失败 | 原位提示 + 重试按钮 | 不得显示虚假成功数据 |
| 断网 | 顶部出现离线条，写操作禁用并说明原因 | 读操作使用缓存数据并标注「可能不是最新」 |
| 乐观更新失败 | 卡片回弹 + Toast + 重试 | 不得留下虚假 UI 状态（US-006 硬性要求） |
| 无权限 | 403 页面 + 返回按钮 | 不泄露其他工作区信息 |

## 7. 导航与操作路径

### 7.1 三层导航模型

| 层级 | 载体 | 承载内容 | 示例 |
|---|---|---|---|
| **全局层** | 侧边栏 + 命令面板 | 跨页面跳转 | 概览 / 任务 / AI 拆解 / 设置 |
| **上下文层** | 内容区顶部工具栏 | 当前视图的控制 | 看板⇄列表、筛选、排序、搜索、新建 |
| **对象层** | 详情抽屉 | 单个任务的全部操作 | 改状态、编辑描述、删除 |

### 7.2 导航设计原则

1. **深度不超过 3 层**即可到达任意对象。
2. **高频动作不超过 1 次按键**：新建（`N`）、搜索（`/`）、切视图（`B`/`L`）。
3. **视图状态全部进 URL**，可分享、可后退、可刷新还原。
4. **面包屑只出现在对象详情页**，列表与看板页不显示面包屑（避免无效层级噪音）。
5. **删除操作采用二次确认**（与现有 `<details>/<summary>` 实现一致）；「执行 + 5 秒撤销」为后续可选优化，待 Toast 撤销链路落地后再评估。
6. **当前所在位置始终可见**：侧边栏激活项 + 浏览器标题 + 面包屑三处一致。

### 7.3 键盘地图

| 按键 | 动作 | 生效范围 |
|---|---|---|
| `⌘K` / `Ctrl+K` | 打开命令面板 | 全局 |
| `N` / `C` | 新建任务 | 全局（非输入态） |
| `/` | 聚焦搜索框 | 列表 / 看板 |
| `G` 然后 `O` / `I` / `S` | 跳转 概览 / 任务 / 设置 | 全局（序列键，Gmail 式） |
| `B` / `L` | 切换看板 / 列表视图 | 任务页 |
| `↑` `↓` | 列表内移动焦点 | 列表 |
| `⌘↑` / `⌘↓` | 卡片移动到上一列 / 下一列 | 看板（卡片聚焦时） |
| `⌘Enter` | 提交表单 / 确认创建 | 抽屉、弹窗 |
| `Esc` | 关闭当前层（抽屉 → 弹窗 → 清空搜索） | 全局 |
| `?` | 快捷键帮助浮层 | 全局 |

**冲突处理**：输入框聚焦时禁用除 `Esc` 与 `⌘Enter` 外的所有单键快捷键；`⌘` 组合键始终生效。

### 7.4 移动端操作路径

桌面端的拖拽在移动端不可用，必须给出等价路径：

```
底部 Tab：[概览] [任务] [AI 拆解] [更多]
  ├─ 默认进入「任务」的列表视图（而非看板）
  ├─ 长按卡片 → 底部 Sheet 弹出状态选择（每项行高 44px）
  ├─ 右下悬浮按钮（56px，距底 72px）新建任务
  ├─ 输入框字号 ≥16px（防 iOS 自动缩放）
  └─ 看板降级为「列 Tab + 单列纵向滚动」
```

## 9. 可访问性规范（WCAG 2.1 AA）

| 维度 | 要求 |
|---|---|
| 对比度 | 正文 ≥ 4.5:1；大字号（≥18.66px 或 ≥24px）≥ 3:1；UI 边界与图形 ≥ 3:1 |
| 焦点 | 所有可交互元素有可见焦点环（2px `--focus-ring` + 2px offset）；**禁止直接移除 outline 而不提供替代** |
| 键盘 | 全部功能可键盘完成；拖拽必须有键盘替代（`⌘↑`/`⌘↓`） |
| 语义结构 | 使用 `nav` / `main` / `aside` / `header`；标题层级不跳级；抽屉与弹窗用 `role="dialog"` + `aria-modal` |
| 触控目标 | ≥ 44 × 44px，相邻目标间距 ≥ 8px（移动端） |
| 表单 | `label` 显式关联；错误通过 `aria-describedby` + `aria-invalid` 播报；错误文案告诉用户「怎么改」而非「你错了」 |
| 颜色独立性 | 颜色不作为唯一信息载体：状态必带文字，优先级必带图标 |
| 动效 | 尊重 `prefers-reduced-motion`；不使用闪烁内容 |
| 文本缩放 | 浏览器缩放至 200% 时布局不破版、不出现横向滚动 |
| 实时播报 | 乐观更新成功/失败、AI 生成完成等异步结果通过 `aria-live="polite"` 播报 |

## 11. 与 v1.0 的差异说明

| 维度 | v1.0（`ui-mockups.md`） | v2.0（本方案） | 变更理由 |
|---|---|---|---|
| 色彩组织 | 直接列出 hex 列表 | 三层令牌（原始 → 语义 → 组件） | 换肤与加密度无需改组件 |
| 主题机制 | 仅深色 | 深色 + 浅色，同一套令牌 | 浅色是长尾场景的可用性保障 |
| 紫色定位 | 品牌强调 + 进行中状态共用 | 紫色独占品牌与交互，状态色独立 | 消除看板上品牌与状态的视觉冲突 |
| 层级表达 | 沿用浅色阴影思路 | 深色改为「边框 + 微投影」双通道 | 深色下传统阴影几乎不可见 |
| 键盘能力 | 仅提及快捷键提示 | 完整键盘地图 + 拖拽的键盘替代 | 无障碍为硬性要求，非加分项 |
| 破坏性操作 | 未定义 | 删除采用二次确认；「执行 + 撤销」为可选优化 | 与 `<details>` 渐进增强实现一致 |
| 信息架构 | 页面清单 | 站点地图 + 三层导航 + URL 状态契约 | 与 `architecture.md` 通道 D 对齐 |
| 响应式 | 「桌面优先，后续适配」 | 六档断点行为对照表 | 让降级路径可预先设计 |
| 深浅色实现 | `prefers-color-scheme` | `[data-theme]` 属性驱动 | 支持用户在设置页手动覆盖 |

## 12. 附录：术语对照

| 术语 | 含义 |
|---|---|
| 应用外壳 App Shell | 侧边栏 + 顶栏 + 内容区的固定框架，所有业务页面共用 |
| 语义令牌 | 以用途命名（`--bg-canvas`）而非以颜色命名（`--black`）的变量 |
| 乐观更新 | 先更新本地 UI 再等服务端确认，失败则回滚 |
| 抽屉 Drawer | 从侧边滑出的容器，桌面承载对象详情，不离开当前上下文 |
| 序列键 | 先按 `G` 再按 `O` 表示「去概览」，无需同时按住修饰键 |
| 五态 | idle / loading / empty / error / success，异步交互必须全覆盖 |
