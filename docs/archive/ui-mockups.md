## 1. 设计系统概览

### 1.1 色彩规范

| 用途          | 色值                     | 说明                 |
| ------------- | ------------------------ | -------------------- |
| 背景主色      | `#0a0a0b` / `#0f1011`    | 近黑背景             |
| 表面层级      | `#141516` / `#18191a`    | 卡片、侧边栏         |
| 主文字        | `#f7f8f8`                | 标题、重要内容       |
| 次要文字      | `#8a8f98`                | 描述、辅助信息       |
| 边框          | `rgba(255,255,255,0.08)` | 分割线、卡片边框     |
| 品牌强调色    | `#5e6ad2`                | 按钮、激活状态、链接 |
| 成功 / 完成   | `#27a644`                | Done 状态            |
| 警告 / 进行中 | 橙色系                   | In Progress          |
| 优先级高      | 红色 / 紫色              | High Priority        |

### 1.2 字体与间距

- **字体**：Inter（或系统无衬线字体）
- **标题**：字重 510–600，适当负字距
- **正文**：字重 400–450
- **间距**：8px 基准网格，卡片内边距 12–16px，列间距 16–24px
- **圆角**：卡片 8–12px，按钮 6–8px

### 1.3 整体风格原则

- 深色优先（Dark-first）
- 信息密度高但不拥挤
- 紫色强调色仅用于关键交互元素
- 支持键盘快捷键提示（`⌘K`、`N` 等）
- 桌面端优先，响应式适配

## 2. 页面效果图说明

### 2.1 登录页（Login）

**路径建议**：`/login`

**设计要点**：

- 左侧：品牌 Logo + 标语「Ship faster with AI-powered tasks」
- 右侧：登录卡片（邮箱、密码、Sign in 按钮、GitHub 登录）
- 极简、居中、高对比度
- 支持「忘记密码」链接

**关键元素**：

- Logo（紫色 T 图标）
- Email / Password 输入框
- 主按钮「Sign in」（紫色）
- 次要按钮「Continue with GitHub」

**交互说明**：

- 表单校验失败时显示错误提示
- 登录成功后跳转至 Workspace 看板

---

### 2.2 看板视图（Kanban Board）——核心页面

**路径建议**：`/issues?view=board` 或 `/board`

**设计要点**：

- 左侧固定侧边栏（Workspace 切换、导航、收藏、用户信息）
- 顶部工具栏：搜索、视图切换（Board / List）、新建按钮
- 主区域四列：
  - **Backlog**（灰色）
  - **Todo**（蓝色）
  - **In Progress**（紫色）
  - **Done**（绿色）
- 每张卡片包含：标题、Issue ID、优先级标签、负责人头像、状态标签

**关键交互**：

- 拖拽卡片改变状态（需持久化）
- 列顶部「+」快速创建 Issue
- 支持列折叠 / 隐藏
- 空状态友好提示

**技术落地点**（对应招聘要求）：

- DOM 事件与拖拽（原生或 `@dnd-kit`）
- 乐观更新 + 错误回滚
- 异步状态同步

---

### 2.3 列表视图（Issue List）

**路径建议**：`/issues?view=list`

**设计要点**：

- 高密度表格式列表
- 列：Status、ID、Issue 标题、Priority、Assignee、Labels
- 顶部筛选栏 + 「New Issue」按钮
- 支持分组（Group by）与排序（Sort）

**关键元素**：

- 状态彩色圆点
- 优先级上下箭头 + 颜色
- 标签（小胶囊）
- 负责人头像 + 姓名

**交互说明**：

- 点击行进入详情或打开侧边抽屉
- 支持批量选择（后续可扩展）
- 搜索实时过滤

---

### 2.4 创建 Issue 弹窗 / 侧边抽屉

**触发方式**：点击「New Issue」或快捷键 `C` / `N`

**设计要点**：

- 右侧滑出抽屉或居中 Modal
- 字段：
  - Title（必填）
  - Description（支持 Markdown）
  - Status、Priority、Assignee
- 突出的 **「AI Breakdown」** 紫色按钮（核心差异化功能）

**交互说明**：

- 标题为空或超长时阻止提交并提示
- 点击 AI Breakdown 后进入拆解结果页
- 支持快捷键关闭（`Esc`）

---

### 2.5 AI 任务拆解结果页

**触发方式**：在创建 Issue 时点击「AI Breakdown」

**设计要点**：

- 展示原始用户输入
- AI 生成的子任务列表（可勾选、可编辑标题、可调整优先级）
- 底部操作：「Cancel」+ 「Confirm & Create All」
- 支持「Regenerate Breakdown」

**关键交互**：

- 用户可修改 AI 结果后再批量创建
- 显示子任务数量与优先级图例
- 失败时提供人工兜底（直接创建原任务）

**技术落地点**：

- 服务端 AI 调用 + Schema 校验
- 超时、重试、取消（AbortController）
- 加载态与错误态处理

---

### 2.6 Workspace 概览 / 仪表盘（可选）

**路径建议**：`/` 或 `/overview`

**设计要点**：

- 问候语 + 今日工作概览
- 统计卡片：Open Issues、In Progress、Completed this week
- 最近活动流（Recent Activity）
- 迷你看板预览（Kanban Preview）

**用途**：

- 登录后的默认落地页
- 快速了解当前工作状态
- 引导用户进入看板或列表

## 4. 响应式与可访问性要求

- **桌面优先**：最小支持宽度 1280px
- **平板**：侧边栏可折叠
- **移动端**（后续）：底部导航 + 列表优先，看板简化为单列滑动
- **可访问性**：
  - 足够的颜色对比度
  - 键盘可完整操作
  - 焦点状态清晰可见
  - 支持 `prefers-reduced-motion`
